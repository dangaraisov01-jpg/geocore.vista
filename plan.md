# Редизайн публичного портфолио Geocore.vista

Работать только в `/home/ubuntu/geocore.vista`, ветка `feat/editorial-portfolio-redesign`. Рабочее приложение GEOLOG-STUDIO, Firebase, пользователи, ключи и данные не затрагиваются. Существующий лендинг заменяется современной статической продуктовой витриной с небольшими интерактивными переключателями демонстраций. Production не публиковать без отдельного разрешения; предоставить preview и PR.

## Дизайн

Направление: editorial Swiss / industrial material study — серьёзная технологическая компания с геологической специализацией. Принципы: чёткая иерархия, одна мысль на экран, демонстрация вместо длинных объяснений, честные проверяемые утверждения. Палитра: тёмный нефтяной зелёный #142824 для уверенности; тёплая бумага #f5f3ec для чтения; медный #c9613c — узнаваемый акцент минерализации. Без ярких градиентов, псевдо-3D бурения и декоративного шума.

Композиция: асимметричный крупный первый экран, левое выравнивание, чередование светлых редакционных секций и тёмных продуктовых демонстраций. Фирменные элементы: ступенчатый знак слоёв, тонкие измерительные линии, цветные геологические полосы. Типографика: Unbounded для выразительных Cyrillic заголовков, Golos Text для коротких удобочитаемых пояснений, IBM Plex Mono для глубин, ID и технических подписей. Контролируемые короткие transition, без бесконечной анимации; учитывать prefers-reduced-motion.

Бренд: единая рабочая среда геолога от устья до готового документа. Характер: точный, собранный, современный. Голос: «От устья до готового акта.»; «Одна скважина. Все связанные данные.» Логотип: компактный знак из трёх сдвинутых слоёв с медным акцентом и набранное имя Geocore.vista.

## Содержание

1. Первый экран с понятным позиционированием, оригинальной предметной фотографией керна и переходом к обзору.
2. Краткий маршрут данных: проект → документация → контроль → результат.
3. Наглядный обзор пяти рабочих областей: проекты, GIS, геологические журналы, керн/QAQC, акты/экспорт. Переключатели демонстраций используют только встроенные вымышленные demo-данные, не отправляют запросов в Firebase. Иллюстрации явно подписаны как демонстрационные, не выдаются за точные screenshots приложения.
4. Семь модулей журнала представлены компактно, без многостраничных документов. Геомеханика и Sampling показываются краткими таблицами/графикой.
5. Импорт/экспорт для профильных программ описан как подготовка таблиц, не выдумывать прямые интеграции и партнёрство. Не показывать логотипы как список клиентов.
6. Работа на участке и в команде: offline очередь, видимые статусы, компании/роли и подтверждённые ключи; не обещать абсолютную защиту, полное шифрование аудита или сертификаты.
7. Краткий FAQ, переход в реальное приложение. Не выдумывать компанию, число клиентов, статистику эффективности, контакты или отзывы.

## Структура

`src/App.tsx` — композиция; `src/components/showcase/` — навигация, продуктовые preview и нижние разделы; `src/data/demoData.ts` — существующие вымышленные примеры; `src/index.css` — новая responsive визуальная система; `public/images/` — единственное original core hero; `scripts/prerender.mjs` — статический HTML public страницы через React server render; `index.html` — SEO metadata, загрузка шрифтов; `public/manus-routes.json` — один маршрут `/`.

Оставить React/Vite, устранить конфликт исходных версий dependencies с фиксированными совместимыми версиями и lockfile. Содержимое доступно crawler без JS через prerender, UI гидратируется. Canonical не придумывать пока production origin портфолио не определён. Статическая сборка и preview без backend.

## Доработка: подлинные демонстрации приложения

Заменить иллюстративные сцены скриншотами реального интерфейса, снятыми из локальной неизменённой сборки GEOLOG-STUDIO в изолированном гостевом браузере только на встроенных 10 demo скважинах. Разрез — экспорт непосредственно исходного SVG renderer; акты — оригинальный генератор и исходная печатная форма A4, не новые маркетинговые шаблоны. Добавить просмотр в полном размере и скачивание настоящих результатов (SVG/PDF). Capture скрипт и provenance сохранять в витрине, рабочий репозиторий не редактировать. Сеть Firebase при съёмке блокировать. Обновить явный блок защиты: проекты/скважины AES-GCM, подтверждение ключей и разграничение доступа; не обещать полное шифрование всех служебных документов.
